# Deployment & Operations

INBOX9 has one Node HTTP runtime (server.js) which mounts the existing API route modules and serves the browser client. The route modules remain independently usable by a compatible hosting adapter.

## Local development

Requirements: Node.js 22+.

```bash
npm run check
npm test
npm start
```

The local server listens on port 4173 by default.

Basic checks:

```bash
curl http://localhost:4173/api/health
curl http://localhost:4173/api/services
```

For a full synthetic lifecycle smoke (register → catalog → activation → 20-second OTP → logout):

```bash
npm run staging:smoke
```

Without PostgreSQL, the runtime intentionally uses the repository's mock session mode and in-memory synthetic activation lifecycle. This is for local development only.

## Runtime architecture

```text
Browser
  │
  └── same-origin /api/*
          │
          ▼
      server.js
          │
          ├── auth / wallet / activation API modules
          │
          └── static client assets
                    │
                    ▼
            Internal synthetic engine
```

dev-server.js remains only as a compatibility launcher and does not contain a second API implementation.

## Hosting requirements

A production hosting environment should provide:

- Node.js 22 or newer.
- A process/runtime that executes server.js.
- Persistent PostgreSQL for account, wallet, activation and inventory state.
- Shared Redis-compatible rate limiting when production rate limiting is enabled.
- HTTPS and a stable canonical application origin.
- Secure environment-variable storage for secrets.
- A scheduler, task runner, or external cron service for periodic reconciliation.

The exact reverse proxy, process manager, container, platform, domain and scheduler can be selected independently of the application code.

## Environment

Start from .env.example or .env.staging.example. Do not commit real credentials.

Required production infrastructure:

```text
DATABASE_URL=
DATABASE_SSL=true
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
APP_ORIGIN=https://your-domain.example
CRON_SECRET=<long-random-secret>
INBOX9_UPI_ID=<your-UPI-ID>
```

Provider credentials are not required for the current synthetic-only build. No external provider API is called by the browser or synthetic engine.

## Staging validation

For persistent staging:

1. Provision PostgreSQL and run `npm run db:migrate`.
2. Run `npm run db:verify` and require `ok: true`.
3. Start `server.js`.
4. Run `npm run staging:smoke` with a funded staging test account (`STAGING_EMAIL` and `STAGING_PASSWORD`) or use the script's local mock mode.
5. Confirm the smoke reaches `Completed` and returns a six-digit synthetic OTP after 20 seconds.
6. Confirm the test account's activation, wallet debit and terminal state in PostgreSQL.
7. Run `npm run issue9:e2e` and `npm run synthetic:smoke`.

The staging smoke never calls an external SMS/OTP provider. The 20-second OTP is generated by the internal synthetic lifecycle.

## Reconciliation scheduling

The reconciliation endpoint is:

```
/api/internal-provider-reconcile
```

It accepts the configured scheduled-job secret using:

```
Authorization: Bearer <CRON_SECRET>
```

The repository also includes `.github/workflows/reconcile.yml` as one optional scheduler implementation. A different scheduler can call the same endpoint; the application does not depend on GitHub Actions.

## Production readiness

Before enabling real traffic:

1. Provision PostgreSQL and run `npm run db:migrate`.
2. Run `npm run db:verify` and require `ok: true`.
3. Configure the shared rate limiter.
4. Configure `APP_ORIGIN` for the final HTTPS origin.
5. Configure a strong `CRON_SECRET`.
6. Configure the real recharge destination.
7. Run `npm run check` and `npm test`.
8. Run `npm run issue9:e2e` and `npm run synthetic:smoke`.
9. Configure a scheduler to invoke reconciliation.
10. Verify `/api/health` reports the required production dependencies as ready.

Production state-changing endpoints fail closed when required shared services are missing. No production credential belongs in Git.
